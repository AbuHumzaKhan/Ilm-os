# Ilm-os Development Plan

## Phase 0 — Foundation

- Establish project vision and scope.
- Establish repository documentation.
- Define architecture boundaries.
- Define development workflow.
- Define the first learning-engine contract.
- Select the initial technology stack only after requirements are understood.

## Phase 1 — Learning Engine Core

Build the reusable engine before expanding the skill catalog.

Target capabilities:

- skill representation
- topic and concept representation
- prerequisites
- learning objectives
- curriculum structure
- lesson model
- exercise model
- assessment model
- learner progress
- mastery state

## Phase 2 — Learning Experience

Build the first complete learner workflow:

`Discover Skill → Curriculum → Lesson → Practice → Help → Assessment → Mastery`

## Phase 3 — First Reference Skill

Use one carefully selected skill to validate the engine end-to-end. The initial reference skill should expose the need for structured content, practice, assessment, and real-world application.

## Phase 4 — Interactive Learning Workspaces

Introduce domain-specific environments where required, such as:

- spreadsheet workspace
- SQL editor
- Python editor
- visualization/simulation workspace

## Phase 5 — Initial Skill Libraries

Expand from the reference skill into Excel, SQL, Python, Data Analytics, Git & GitHub, Business Analysis, Data Modeling, Power BI, Statistics, and other priority domains.

## Phase 6 — AI Tutor and Personalization

Add contextual tutoring, learner-aware explanations, hints, adaptive difficulty, and question answering grounded in the current lesson and learner state.

## Phase 7 — 20+ Skills

Validate that the common engine can support multiple domains without domain-specific architectural duplication.

## Phase 8 — 50+ Skills

Build and curate a professional skill catalog using the common learning model.

## Phase 9 — Production Hardening

Security, performance, accessibility, observability, testing, content quality, deployment, backups, documentation, and contributor workflows.

## Phase 10 — Public Release

Publish the stable open-source platform and establish contribution and content-quality processes.

## Rule

Never advance to a later phase merely because it is interesting. A phase advances only when its acceptance criteria are satisfied.
