# Contributing to Ilm-os

Thank you for helping improve Ilm-os.

## Before You Start

Read:

1. `README.md`
2. `docs/MIND.md`
3. `docs/DEVELOPMENT_RULES.md`
4. `docs/CURRENT_STATUS.md`
5. `docs/ARCHITECTURE.md`

## Development Principles

- Keep changes focused.
- Do not introduce new architecture without documenting the reason.
- Prefer reusable Learning Engine capabilities over skill-specific duplication.
- Keep educational content accurate and practical.
- Add tests for behavior that can be tested automatically.
- Update documentation when a change affects project behavior or architecture.

## Skill Content Contributions

Skill libraries should contain structured, practical learning material rather than collections of disconnected explanations.

A substantial skill should define prerequisites, objectives, lessons, practice, assessment, common mistakes, and real-world application where appropriate.

## Pull Requests

A pull request should explain:

- what changed
- why it changed
- how it was tested
- whether documentation was updated
- whether the change affects architecture or learner experience

Avoid mixing unrelated features in one pull request.
